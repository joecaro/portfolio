## What it is

When an AI voice agent handles a call, the transcript is the easiest thing to read and the least trustworthy. The agent can say "your payment went through" whether or not it did. If a review tool blurs what the agent said with what it actually did, a broken call looks like a good one.

I built two tools for this in the platform's operations console:

- A **call-details redesign** that puts the transcript front and center, with the recording, the agent's tool calls, and its safety checks on one synced timeline. Click a tool call and you jump to the turn and the moment in the audio where it happened.
- A **call-flow map** that shows how a whole set of calls moves through the agent's stages, including where calls loop back.

I set the goals and made the design calls. Coding agents wrote much of the code, and separate agents reviewed it before I signed off.

## The call-flow map

This one is merged. The ask was simple: the graph is the default view, there's a list view for people who'd rather scan, both views share one selection, and the card always says how much of the data it actually covers.

Coverage sounds boring but it's the important part. The old subtitle said something like "287 of 300 calls" and left you to work out whether that was the whole picture. Now it says things like "287 of 300 calls analyzed · Partial coverage," or "coverage unknown" when we don't know. Line width is call count, and the footer says outright that calls can show up in several stages.

The interesting bug was about loops. A "return" edge (a call going back to an earlier stage) is drawn dashed. The graph decided what counted as a return using column plus vertical position. The list used column only. So the same edge could be a return in one view and not in the other. Review caught it in two rounds: first that upward edges in the same column lost their dashes, then that just reordering nodes could flip the answer. The fix was one rule, column order only, used by both views, with a regression test. I also changed returns from rose to neutral gray. Red made a normal retry look like an error.

It merged with targeted tests, typecheck, lint, an independent review of the exact commit and CI. I haven't validated it at narrow phone widths or on touch yet.

## Call details, take one

My first pass at the call-details view was an opt-in turn view. Looking at it with real data, I threw most of it out. It made up timing when the logs didn't have any, it guessed which turn an event belonged to, and it showed empty inspector panels for steps that never happened. The only part I kept was the code that maps raw turn logs into a clean structure.

## Call details, take two

The second version starts from the transcript. The recording and timeline live in a resizable rail on the right. The timeline has lanes for the customer, the agent, the model, tools, and safety checks, all on the same clock as the audio. Each turn has a "Turn details" dialog with timing (speech-to-text, model wait, text-to-speech, and so on), the model run, the tools it had, and the prompt.

The waveform has limits on purpose. It's capped at 2,000 peaks, decodes at a low sample rate, and skips recordings over 20 minutes or 20 MB, so a long call can't freeze the page.

An independent review found four bugs, all fixed:

- Events with no timestamp were drawn at 0:00, which made them look like they happened at the start.
- If a turn had no time, it borrowed the earliest tool event's time instead.
- The "Playing" cue stayed on after you paused.
- The call ID was hidden behind a disclosure.

The rule behind all four: if the data doesn't say, the UI shouldn't guess. Untimed events now go in a separate "Activity not placed on the timeline" list, and missing times show a dash labeled "Time not recorded."

I also checked it against one masked real call, which caught a text-wrapping bug the fixtures missed. A couple of design calls went my way against the reviewer's advice: no chat bubbles, and keep the colored reply-type pills, because people scanning dozens of calls need to spot scripted or sensitive replies fast.

The test count went from 111 to 138 over two days.

## Where it stands

The call-flow map is merged. The call-details redesign is unmerged and in review. It's behind an opt-in switch for internal users, on calls that have turn logs, and it hasn't been released. I don't have usage numbers for either.
