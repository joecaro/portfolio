*Part of [Tools for Operating Voice Agents](/projects/voice-ai-platform), for reviewing one call or exploring flow across many.*

## Separate what was said from what happened

An agent can say “you're all set” without completing the action. The call-details workspace keeps the transcript beside the recording, tool calls and safety checks on a shared timeline. Selecting an event links the relevant turn with its place in the audio. Missing timestamps remain explicitly unplaced instead of being drawn at the start of the call.

The call-flow map gives a different view: a graph and list of the stages calls passed through, with shared selection and an explicit coverage statement. Line width represents call count, and the interface notes that a call can appear in multiple stages.

## One rule for graph and list

The graph and list initially classified return edges differently. A call that looped back could appear as a return in one view and an ordinary transition in the other. I unified classification around column order and used that rule in both views, with a regression test.

The map is merged to main. Targeted tests, type checking, lint, CI and an independent review covered the change. I have not validated its layout at narrow phone widths or on touch.

## Rebuilding the call timeline

An early turn view inferred timing from incomplete logs and showed empty panels for events that never happened. I replaced it with a transcript-first layout and a recording/timeline rail. Timed events share the audio clock; untimed events appear in a separate activity list. Turn details include available timing, model, tools and prompt information.

The waveform is bounded to 2,000 peaks and skips recordings over 20 minutes or 20 MB. A masked real call exposed text wrapping that fixtures had missed. Review also caught timeline placement and playback-state bugs, which I corrected.

## Status

The call-flow map and transcript-first call-details view are merged to main. The port into one enterprise customer's separate build failed on its first attempt; I reverted it, added baseline tests for the old screen and the corrected port is in review. Usage is not measured. The demo above shows both interfaces with a fictional call.
